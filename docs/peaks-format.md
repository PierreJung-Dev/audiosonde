# Peaks artifact format (consumer guide)

The `peaks` analyzer produces one artifact **per requested zoom level**, generated by BBC
[`audiowaveform`](https://github.com/bbc/audiowaveform), in one of two formats:

- `audiowaveform-dat` — the compact binary `.dat` format (below), ideal for players like
  [peaks.js](https://github.com/bbc/peaks.js) or custom canvas renderers.
- `json` — the same data as JSON: `{ version, channels, sample_rate, samples_per_pixel,
  bits, length, data: [min, max, min, max, …] }`.

A **zoom level** is `samplesPerPixel`: how many source samples each min/max pair spans.
Zoom 256 at 44.1 kHz ≈ 172 pairs per second of audio.

## Binary `.dat` layout (little-endian)

| Offset | Type | Field |
|---|---|---|
| 0 | int32 | `version` — 1 (mono mix, the default) or 2 |
| 4 | uint32 | `flags` — bit 0: `1` = 8-bit resolution, `0` = 16-bit |
| 8 | int32 | `sample_rate` (Hz) |
| 12 | int32 | `samples_per_pixel` (the zoom level) |
| 16 | uint32 | `length` — number of pixels (min/max pairs per channel) |
| 20 | int32 | `channels` — **version 2 only** (version 1 is always 1 channel) |
| 20 / 24 | int8[] / int16[] | `length × channels` interleaved `[min, max]` pairs |

8-bit values span −128…127; 16-bit span −32768…32767. The engine emits version 1
(audiowaveform's mono mix-down) with 8-bit resolution unless `bits: 16` is requested.

## Decode example (Node.js / browser-compatible)

```js
function decodePeaks(buf /* DataView | Buffer over the .dat bytes */) {
  const view = buf instanceof DataView ? buf : new DataView(buf.buffer, buf.byteOffset, buf.byteLength);
  const version = view.getInt32(0, true);
  const flags = view.getUint32(4, true);
  const bits = (flags & 1) === 1 ? 8 : 16;
  const sampleRate = view.getInt32(8, true);
  const samplesPerPixel = view.getInt32(12, true);
  const length = view.getUint32(16, true);
  const channels = version === 2 ? view.getInt32(20, true) : 1;
  let offset = version === 2 ? 24 : 20;

  const read = bits === 8
    ? (o) => view.getInt8(o)
    : (o) => view.getInt16(o, true);
  const step = bits === 8 ? 1 : 2;
  const scale = bits === 8 ? 128 : 32768;

  // pairs[channel][pixel] = { min, max } normalized to -1…1
  const pairs = Array.from({ length: channels }, () => []);
  for (let px = 0; px < length; px += 1) {
    for (let ch = 0; ch < channels; ch += 1) {
      const min = read(offset) / scale; offset += step;
      const max = read(offset) / scale; offset += step;
      pairs[ch].push({ min, max });
    }
  }
  return { version, bits, sampleRate, samplesPerPixel, length, channels, pairs };
}
```

Rendering is then one vertical line (or thin rect) per pixel:

```js
const { pairs, length } = decodePeaks(datBytes);
for (let x = 0; x < length; x += 1) {
  const { min, max } = pairs[0][x];
  // y-axis: 0 at the vertical center, min/max in -1…1
  canvasCtx.fillRect(x, mid - max * mid, 1, Math.max(1, (max - min) * mid));
}
```

The integration test `test/integration/peaks.test.ts` keeps a decoder matching this layout
and runs it against real engine output in CI — if this document drifts from reality, CI
fails.
